# Troubleshooting

## Plugin will not enable

Confirm Paper 26.2 and Java 25. Read the first configuration exception. For an incompatible earlier data folder, archive it and let the clean rewrite create fresh defaults.

## Reload rejected

Fix the reported YAML path, unknown material/type/rarity/rod, invalid range, missing GUI icon, or EN/IT scalar mismatch. The active snapshot is still running.

## Market unavailable

Install Vault and a compatible economy provider, then restart. Vault alone is not an economy.

## Fishing animation happens but no custom fight

With a managed rod, a valid `CAUGHT_FISH` now either commits a custom session before suppressing native loot or leaves the native catch intact. `FAILED_ATTEMPT` means the bite timing was missed; `REEL_IN` means the hook was reeled without a bite. Enable `debug.fishing-events: true`, reproduce once, and inspect the concise player/state/hook/eligible/selection/fallback decision. Disable it after diagnosis.

## Shop unavailable

Check `/fishingadmin shop status`, the persistent override, both category switches, the entry's `shop.enabled`, Vault, and the economy provider. Shop unavailability does not disable fishing.

## Bait not accepted

Use bait generated by the shop or `/fishingadmin bait give`; a visually identical normal item fails signed PDC authentication. Hold the same rod used to open the loader, do not move/drop it, and respect the configured bait stack limit.

## Fish not catchable in a region

Check explicit `integrations.denied-fishing-regions`, species `conditions.regions`, WorldGuard availability, and all other conditions. Bait cannot override a region or depth mismatch.

## A species never appears

Check rod allow-lists and every condition. Region-restricted species require enabled WorldGuard and a matching applicable region. Luck never bypasses a condition.

## Resource-pack model missing

Validate the namespaced `item-model`, custom model data, and client pack version.

## Database busy or reset failed

Check disk permissions/free space and the logged SQLite cause. Never delete the database during runtime. Use the timestamped snapshot for recovery on a stopped server.
